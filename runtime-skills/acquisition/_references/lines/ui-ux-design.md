# Line: UI/UX Design

## What "good" looks like

- **Onboarding** — 3 or fewer required-field screens before first meaningful action, a
  progress cue on multi-step flows, clear error copy attached to the offending field.
- **Consistency** — one button style, one type scale and one spacing rule across primary
  flows. A design system, not one-off screens.
- **Accessibility (AA)** — labelled controls, focus-visible states, 4.5:1 contrast for
  text, 3:1 for icons, no keyboard traps.
- **Mobile layout** — targets ≥ 48 px, no truncated primary CTAs, no horizontal scroll.

## Common problems and how to recognise them from evidence

| Problem | Evidence |
|---|---|
| Usability complaints in reviews | 3+ recent 1–3 star reviews naming friction, confusion or missing basics. |
| High-friction sign-up | Onboarding capture shows > 4 required-field screens with no progress cue. |
| Inconsistent UI | Heuristic capture: 3+ inconsistencies between two flows. |
| Accessibility failures | Automated check flags ≥ 3 WCAG AA issues on primary flows. |
| Weak mobile layout | Layout breaks at 375 px on primary screens. |

## Business impact in plain language

- **Fewer sign-up drop-offs.** Every extra required field loses users; users don't email
  support to complain, they just leave.
- **Reviews reach every future customer.** A one-line usability complaint in an App
  Store review is a permanent lead-loss.
- **Accessibility fixes are the cheapest form of growth** — you're already paying for
  the traffic.

## Vocabulary — for non-technical stakeholders

Use: onboarding, sign-up, flow, drop-off, friction, accessibility, mobile layout, error
message, progress cue, design system.

Avoid without explanation: heuristic, WCAG, ARIA, cognitive load, information
architecture, Fitts's law, affordance.
